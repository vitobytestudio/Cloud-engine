# VDB — قاعدة بيانات فيتو (VITO BYTE DATABASE)

أول قاعدة بيانات تخزين من صنع استوديو VITO BYTE — مبنية من البايتة الأولى داخل المستودع، بلا أي اعتمادية خارجية، بالتايبسكريبت الصارم، وتخدم منصتَي nexus وnaksab كعتاد مشترك.

## العمارة (مثبتة الصنع لا مُختلَق)

- **صفحات 4096 بايت** مرقّمة فوق طبقة كتل عمياء (`BlockStore`): الذاكرة للفحص، وWorkers KV للسحابة، وأقراص عنقودنا الخاص غداً — بلا تغيير سطر واحد في المحرك.
- **شجرة B+ بنسخ-عند-الكتابة الصارم** (نموذج LMDB): الصفحات الملتزمة لا تُعاد كتابة أبداً؛ كل تعديل يولّد نسخاً جديدة من مساره حتى الجذر، والوالد يشير للابن الجديد.
- **الالتزام الذري بنقطة واحدة**: كتابة صفحة الميتا (0) — ما قبلها يتيمة بلا ضرر، وما بعدها معتمد كاملاً. الانهيار في أي لحظة يترك آخر حالة جيدة سليمة بحرفها.
- **كاتب واحد مُسلسَل، قراء بلا قفل**: القراءة على لقطة آخر التزام، والكتابة عبر سلسلة تسلسل داخلية.
- **العد الطرقي** (بلا مؤشرات شقيقة): كرسيّ يحمل رحلة النزول، فانقسام الورق لا يكسر العد أبداً.
- **الجيران حثيثاً**: `db.tenant(name).bucket(name)` — الحصص (`maxKeysPerTenant`) تُفرض في باب المحرك.
- **الزمن حثيثاً**: كل التزام يُسجَّل في دفتر `_sys/j` بذات الذرية — بذرة السفر الزمني.
- **العربية في العُظم**: `normAr`/`arKey` — توحيد الهمزات وإسقاط التشكيل والتاء المربوطة في نواة المحرك لا فوقه.
- **مفاتيح مرتِّبة بالبايت**: نصوص وأرقام (float64 مرتِّب) ومركّبات مهرَّبة — الترتيب محفوظ رياضياً ومختبَر خصائصياً.

## الاستعمال

```ts
import { VDB, KVBlockStore, MemoryBlockStore } from "../vdb/src";

const db = await VDB.open(new KVBlockStore(env.CACHE_KV, "vdb:nexus:"), {
  journal: true,
  maxKeysPerTenant: 5000,
});
await db.tenant("nexus").bucket("audit").put("evt-1", { action: "plan_grant", ts: Date.now() });
const rows = await db.tenant("nexus").bucket("audit").list({ limit: 100 });
```

## الحدود الحالية (موثّقة بصدق — لا وهم)

- قيمة ≤ 1500 بايت ومفتاح ≤ 120 بايت (يرمي برسالة واضحة).
- كاتب واحد لكل نسخة محرك؛ عبر عزلات Workers المتعددة التزام إضافي بلا CAS — مرحلة الظل الحالية (سجل تدقيق إلحاقي) متسامحة مع ذلك، وطبقة الكتل على عنقودنا الخاص تمنح قفلاً حقيقياً لاحقاً.
- صفحات الملتزم القديم يتيمة حتى `compact()` — استرجاع المساحة (GC) في الخارطة.

## الإمبراطورية — أقراصنا الخاصة (بعيداً عن KV وD1 معاً)

طبقة الأقراص الحقيقية `src/store-disk.node.ts` (أرض Node حصراً — خارج حزمة السحابة):
سجل كتابة مسبق ملحق-فقط بصمة CRC32 على الحمولة + **fsync إجباري عند كل التزام**،
استرجاع انهيار يقص الذيل الممزق عند الفتح، قفل ملف حصري يجعل عزلات متعددة تلتزم
على نفس الأقراص بحجز الجيل، وقراءة لقطة MVCC من الفهرس بلا مسح.

**عقدة الإمبراطورية** `server/node.mjs`: خادم HTTP يخدم المحرك من أقراصنا —
put/get/list/count/batch/compact + `/vdb/sync` (تغذية النسخ المتماثل بالسجل)
+ `/vdb/dump` و`/vdb/restore` (نسخ احتياطي واستعادة). التوكن إجباري، والبلا توكن 403.

**إطلاق على أي سيرفر نملكه**: `sh vdb/server/launch.sh [PORT] [DATA] [TOKEN]`
أو Docker: `docker build -t vdb vdb/ && docker run -p 8490:8490 -v vdbdata:/vdb/server/data vdb`.

**بوابة الأمبراطورية** `tests/cluster.dev.mjs` — 12 فحصاً بعنقود حي:
ضغط HTTP فعلي، SIGKILL أثناء الكتابة ثم إعادة إقلاع (صفر خسارة)،
نسخة متماثلة تلتزم السجل وتلحق الفارق، وعقدة ثالثة تستقيم من النسخة الاحتياطية.

## الخارطة

1. GC واسترجاع صفحات + قفل موزّع حقيقي فوق طبقة الكتل.
2. فهرس نصي عربي كامل (نغرام/جذر) فوق `arKey`.
3. جيران بمفاتيح تشفير خاصة وسفر زمني بجذور متعددة.
4. طبقة كتل على عنقودنا الخاص → سيادة بيانات كاملة.
