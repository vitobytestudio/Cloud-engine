# VITO BYTE FLOW RELAY — عقدة الأتمتة التفاعلية (الجلسة السحابية المعزولة)

عقدة واحدة صفرية التبعيات تشغّلها المالك على أي جهاز يملكه (حاسوبه الشخصي كافٍ) — المنصة (Workers) تبقى بلا GPU وبلا مفاتيح.

## ماذا تفعل النافذة التفاعلية للزبون؟
1. الزبون يضغط «ربط حساب Google Flow بضغطة واحدة» في المنصة — تفتح نافذة **داخل منصتنا** تضم بثاً تفاعلياً حياً لصفحة **دخول جوجل الرسمية** (CDP `Page.startScreencast` فوق WebSocket صفر تبعيات) — يعمل على الهاتف (أبعاد 390×844 تلقائية من User-Agent) والحاسوب.
2. الزبون يكتب بريده وكلمة السر **بنفسه** ويؤكد التحقق بخطوتين **بيده وبرضاه الكامل** — 2FA والحظر الأمني لجوجل يُحلان بنفسه في نافذته. **لا نلمس كلمة السر في أي حقل لدينا** — ما يمر عبرنا بكسلات الصفحة وأحداث اللمس/الفأرة فقط.
3. المتصفح **غير مكشوف**: Patchright إن وُجد وإلا Playwright، مع إخفاء `AutomationControlled` وإزالة `--enable-automation` — تجنّب رسالة "This browser or app may not be secure".
4. عند وصول الجلسة إلى `labs.google` تُحفظ `storageState` مشفرة لدى المنصة، **يُغلق البث فوراً**، وتظهر «تم الربط بنجاح» — ثم يبدأ التوليد في الخلفية والنتيجة تعود للمنصة.

## التشغيل
```bash
NEXUS_ORIGIN=https://nexus.vitobytestudio.workers.dev \
VBS_RELAY_TOKEN=<نفس سر المنصة VBS_RELAY_TOKEN> \
DRIVER=flow \
PORT=8801 \
node node.mjs
```
- متصفح غير مكشوف (مرة واحدة): `npm i patchright && npx patchright install chromium` — أو `npm i playwright && npx playwright install chromium`.
- خادم بلا شاشة: شغّل داخل Xvfb (`xvfb-run node node.mjs`) أو أضف `HEADLESS=1` (للتوليد فقط — الدخول التفاعلي يفضل رأسه مرفوعاً دائماً لتجنّب حظر جوجل).
- مهلة الدخول الافتراضية 10 دقائق: `LOGIN_TIMEOUT_MIN=15` لتغييرها.
- عنوان النافذة للزبون يصبح `VBS_RELAY_ORIGIN` — على جهاز شخصي يكفي نفق https (مثل cloudflared) ليصبح `https://relay.nطيك`.

## التشغيل 24/7 على GitHub Actions (تلقائي كلياً)
ملف `.github/workflows/flow-relay.yml` يشغّل العقدة كاملة على ubuntu-latest: Xvfb + Patchright/Chromium + نفق cloudflared — كل دورة تعيش **5 ساعات و25 دقيقة**، وقبل انتهائها بعشر دقائق تُطلق دورة جديدة ذاتياً عبر `workflow_dispatch` (تسليم دافئ — العقدة الحية تُخدم حتى تقلع التالية)، وحارس كل 6 ساعات يعيد الإقلاع إن انقطعت السلسلة.

**الأسرار المطلوبة في GitHub Secrets:**

| السر | أين يُضبط | الغرض | إلزامي؟ |
|---|---|---|---|
| `VBS_RELAY_TOKEN` | GitHub + سر عامل نكسوس وناكساب | التوكن المشترك بين المنصة والعقدة — العقدة لا تقلع بدونه | **إلزامي** |
| `VBS_SESSION_KEY` | سر عامل نكسوس فقط | تشفير AES-GCM لجلسات الزبائن — ينقله سلك نشر نكسوس | **إلزامي للمنصة** |
| `CLOUDFLARE_TUNNEL_TOKEN` | GitHub فقط | نفق **ثابت الرابط** (من لوحة كلاودفلير: Tunnel → Hostname) | اختياري |
| — | — | السلسلة الذاتية تستخدم `GITHUB_TOKEN` المدمج بصلاحية `actions: write` — بلا أسرار إضافية | — |

- **بدون** `CLOUDFLARE_TUNNEL_TOKEN`: نفق سريع مجاني `*.trycloudflare.com` يُفتح تلقائياً، ورابطه **يُحدَّث في KV المنصة عند كل إقلاع** (`POST /api/studio/relay/origin`) — المنصة تقرأ الديناميكي تلقائياً (السر الثابت `VBS_RELAY_ORIGIN` يتفوق عند ضبطه، فاتركه فارغاً في وضع النفق السريع). ملاحظة: انتشار KV حتى ~60ث — الدورة الجديدة تقلع قبل موت القديمة بعشر دقائق فلا فجوة.
- مع `CLOUDFLARE_TUNNEL_TOKEN`: رابط ثابت أبداً — اضبط `VBS_RELAY_ORIGIN` كسر ثابت على المنصة بنفس العنوان.
- التشغيل اليدوي الأول: صفحة Actions → «FLOW RELAY» → Run workflow. بعدها السلسلة تدور وحدها.
- ملاحظة المالك: السلسلة على مستودع خاص تستهلك دقائق Actions (~5.5 ساعة/دورة) — على مستودع عام فهي مجانية بالكامل.

## أسرار المنصة (GitHub Secrets — تُنقل للعامل تلقائياً في كل نشر)
- `VBS_RELAY_TOKEN` — التوكن المشترك بين المنصة والعقدة
- `VBS_SESSION_KEY` — 64 خانة hex: تشفير AES-GCM لجلسات الزبائن
- `VBS_RELAY_ORIGIN` — عنوان العقدة كما يراه الزبون (https)

## السائقان
- `DRIVER=mock` — للبوابات والتجارب: ربط فوري + إطارات محاكاة حية عبر نفس جسر WS (تُختبر بـ `ws-gate.mjs` في كل نشر) + توليد فوري برابط عينة.
- `DRIVER=flow` — الإنتاج: الدخول التفاعلي الحقيقي + توليد فعلي على حساب الزبون.

### آلية القيادة المجرّبة (مستقاة من GTAI-1/flow-mcp ★715 — ISC)
سائق التوليد لا يخمّن محددات — إنما يتبع الآلية المجرّبة الحية لواجهة Flow:
1. **مشروع فعلي**: إن لم تكن الجلسة داخل `/project/<uuid>` → زر «New project» وانتظار المشروع.
2. **الإعدادات** (لوحة Settings trigger): راديو «Video|Image» → للفيديو «Frames|Ingredients» (ولا يجتمعان في Flow إطلاقاً) → الأبعاد (9:16/16:9/1:1) → المدة (4s/6s/8s) → x1 → للصور نموذج Nano Banana **الأحدث** يُقرأ من قائمة Flow نفسها (أعلى رقم غير Lite) فلا يتقادم الكود.
3. **الصورة المرجعية**: «Add media menu» → filechooser → «Upload» → ملف باسم فريد `fm-<job>-…` → انتظار معالجة بلاطتها (media-id) 90ث → إرفاقها: edit عبر «Add ingredients to the prompt box» مع تحقق عدد أزرار Ingredient، وi2v عبر زر «Start» (إطار البداية) — كل محاولة فتح للمنتقي ×3 مع Escape بينها كما هو مجرّب عندهم.
4. **البرومبت**: صندوق `.ProseMirror` — سطر واحد (Enter يرسل في Flow) ثم زر «Start generation» مع فحص تفعيله قبل الضغط ولقطة معرفات البلاطات قبله.
5. **انتظار النتيجة**: بلاطات `flow-grid-tile-container` الجديدة غير المرفوعاتنا (`fm-`) وغير المشغولة (نسبة `%` أو فيديو بلا مصغّرة) — استقرار عناوين الفيديو مرتين، وكشف بلاطات الخطأ — مهل الصورة 3د والفيديو 12د.
6. **التقاط الرابط**: لا تنزيل ملفات — رابط الوسائط الحي يُقرأ من بلاط النتيجة نفسه (video/img src) باحتياج مشغل الزبون، وطبقة شمّ استجابات الشبكة احتياطاً — صفر تخزين كما هو أمر المالك.

## الأمان
- كلمة السر لا تمر عبرنا ولا تُخزن ولا تُرى — حقول جوجل الرسمية داخل متصفح العقدة فقط.
- الجلسة (`storageState`) تُرسل للمنصة حيث تُشفَّر AES-GCM مرتبطة بحساب الزبون — العقدة لا تحفظ شيئاً على القرص.
- `unlink` من الواجهة يمحو الجلسة نهائياً فوراً؛ توكنات الربط تُحرق لحظة الاستخدام (TTL 15 دقيقة).
- القناة التفاعلية: توكن لمرة واحدة مفت المشاهدة — مُشاهد جديد يُقصي السابق؛ أحداث الإدخال مقيّدة ومقصوصة.
